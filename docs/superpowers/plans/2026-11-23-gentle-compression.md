# Бережное сжатие видео и изображений

## Состояние на 24 ноября 2026 года

Режим реализован в рабочей копии ветки `codex/gentle-compression`. Контрольная партия прошла через FFmpeg, смешанная очередь — через PyQt в режиме offscreen. Параметры откалиброваны на девяти локальных образцах. Проверка на собственных съёмках пользователя, в том числе на лицах в движении, остаётся открытой.

## Решения для первой версии

- Переключатель **Gentle compression** выключен по умолчанию. Ручные параметры восстанавливаются после выключения. Старые пресеты загружаются с выключенным режимом.
- Один набор эффектов, размеров, аудио и метаданных на вход. Каждая попытка читает оригинал. Приложение сравнивает байты после записи контейнера и метаданных. Первый результат с `0 < output_bytes < input_bytes` сохраняется.
- Видео использует программный H.264, medium, CRF 21 → 23. JPEG использует FFmpeg MJPEG q3 → q4 с optimal Huffman. Повтор выполняется только при отсутствии экономии. PNG использует одну lossless-попытку с уровнем 9 и предиктором mixed. Размер холста и эффекты задаются существующими настройками. В Auto прозрачные входы сохраняются как PNG, а Always JPEG сводит их на белый фон.
- Если экономии нет, файл пропускается. Опция **Keep processed file if size cannot be reduced** сохраняет первую версию. Ошибка второй попытки и отмена прекращают работу над файлом. Временные кандидаты размещаются на выходном томе. Завершённый результат атомарно занимает свободное имя при публикации. Конкурирующие задания получают разные пути.
- HEVC, заданный размер в МБ и автоматическое понижение разрешения выходят за рамки этой версии. Инструкция по использованию находится в README.

## Этапы и результаты

| Этап | Реализация и проверка |
|---|---|
| 1. Зафиксировать базу | До исправлений прошли 93 теста и обе штатные проверки качества. Отдельный экспорт воспроизвёл сбой клипа 0,08 с при 31,2 ГБ свободного места. Для оценки сжатия подготовлен парный эксперимент ниже. |
| 2. Выбрать и опубликовать кандидат | Проверены границы 999/1000/1001 байт, пустой кандидат, пустой и отсутствующий исходник, выбор первой и второй попыток, пропуск и сохранение без экономии. Тесты охватывают сбой второй попытки, отмену, ENOSPC при публикации, подмену имени и два конкурентных экспорта. Исходник и чужие файлы сохраняются. |
| 3. Подключить видео | Повтор использует тот же граф и метаданные. Проверены двухкадровый MP4 и следующий обычный файл в очереди, наличие декодируемых кадров, звук и синхронизация, HLG и PQ → BT.709. Короткие ролики до секунды включительно проходят целиком. Сообщение фильтра о нехватке ёмкости не останавливает весь пакет как заполненный диск. Для ручного режима проверен переход с отказавшего аппаратного кодировщика на libx264. |
| 4. Подключить JPEG и PNG | JPEG измеряется после EXIF. Для PNG с индексированной палитрой, прозрачного WebP и TIFF декодированный RGBA сравнен побайтно с сырым выходом того же графа. Проверены прозрачные, полупрозрачные и непрозрачные пиксели. Отмена завершает зависший процесс обработки изображения и очищает кандидаты. |
| 5. Провести результат через интерфейс | Проверены настройки, старый пресет, сброс, смешанная очередь, одинаковые имена в разных каталогах, пропуски, битый файл, Retry Failed и закрытие окна при активном экспорте. Интерфейс различает обработанные и сохранённые файлы. По каждому результату показывается фактическая экономия. Дополнительное место для параллельных попыток учитывается при оценке перед запуском. |
| 6. Выбрать параметры и описать режим | Испытаны две пары настроек. Сравнены размеры, время и SSIM. Просмотрены фрагменты кадров в масштабе 1:1. Инструкция добавлена в README. |

## Парное сравнение

macOS, Python 3.14.5, FFmpeg 8.1. Для каждого входа параметры были сгенерированы один раз с seed 42 в отдельном последовательном процессе. Между экспортами восстанавливалось одинаковое состояние генератора для графа и метаданных. Для обычного видео использован Match Source. Измерено время одного вызова обработки, включая повторы; эти значения округлены и зависят от текущей нагрузки.

JPEG получены из системных фотографий Big Sur Coastline и Owl. Остальной корпус включает уже сжатые JPEG и MP4, PNG с мелким текстом и тёмным градиентом, панорамирование фотографии, титры, testsrc2 со звуком и три секунды системного деморолика Mouse, предварительно преобразованного утилитой macOS avconvert. Пользовательские файлы не использовались.

Размеры приведены в байтах. «Прежний» — CRF 23/25 и JPEG q4/q5, «выбранный» — CRF 21/23 и JPEG q3/q4. Чтобы измерить качество при пропуске, для эксперимента включали сохранение первой попытки. Её размер указан в скобках. Отдельно подтверждены все результаты с выключенной опцией сохранения без экономии. SSIM рассчитан по декодированным кадрам относительно lossless-выхода того же графа. Оба профиля уменьшили 6 из 9 входов. Выбранный сэкономил 1 151 722 байта при исходном объёме 1 614 760 байт (71,3%, пропуски дают нулевую экономию). На компактном MP4 потребовался повтор с CRF 23. На фотографии совы SSIM вырос с 0,9473 до 0,9584. На увеличенных до натурального масштаба фрагментах видны отдельные перья и контуры букв; у более бережного JPEG больше деталей. На тёмном градиенте сглаживание видно в обоих видеопрофилях. Исходные файлы с особенно высоким битрейтом сильно влияют на общий процент.

## Воспроизведение проверок

Из корня проекта выполнить команды ниже. Вторая и третья проверки запускают штатный контроль эффектов; отдельное сравнение параметров экспорта приведено выше.

~~~sh
rtk proxy env QT_QPA_PLATFORM=offscreen .venv/bin/python -m pytest -ra
rtk proxy .venv/bin/python src/verify_quality.py
audit_dir=$(rtk proxy mktemp -d)
rtk proxy ffmpeg -loglevel error -f lavfi -i testsrc2=s=1600x1200 -frames:v 1 "$audit_dir/photo.jpg"
rtk proxy .venv/bin/python src/verify_quality.py "$audit_dir/photo.jpg"
~~~

Итог проверки рабочей копии: 111 тестов прошли без пропусков, обе штатные проверки качества прошли. Синтетический HDR покрывает теги и преобразование, а визуальная проверка охватывает выбранные кадры. Для окончательной оценки на пользовательском материале нужны оригиналы с лицами в движении, быстрыми сценами и мелкими титрами. Сборка и публикация релиза в эту работу не входят.
